# 领域边界

管理洪灾撤离、安置容量、家庭团聚、敏感需求和救助物资。

现有领域资料围绕以下边界组织：

- 家庭与人员核验
- 撤离和安置容量
- 寻亲团聚
- 物资批次守恒
- 隐私与恢复待办

资料版本只能递增。参与方、事实和约束均不能为空，示例不得包含真实个人信息、账号或凭据。

# 后端实现的不变量

以下规则由 `src/shelter/` 强制，并有 `tests/` 覆盖：

## 家庭与人员核验

- 身份不明者可先建临时档案；档案状态只能为 `unidentified → provisional → verified`。
- 合并只落指针，不删行、不改写；被合并档案的原始接收地点、时间、经办队伍与经办人
  由数据库触发器保护，任何 UPDATE 都被拒绝。
- 合并必须依据一条 `confirmed` 的身份核验；合并记录写入 `person_merges` 与审计日志。
- 通过旧编号查询位置、持有物资时自动解析到当前保留档案，历史记录仍挂原档案可查。

## 撤离和安置容量

- 撤离批次逐人登记登车与到达；未点名到达者标 `no_show`。
- 当前在住人数与无障碍需求人数由移动台账推导，不存在可漂移的缓存计数。
- 容量越限触发满员/85%/无障碍床位预警；同一活跃预警只保留一条，解除后可再次触发。
- 转运导致超员默认拒绝；显式放行必须留痕。

## 寻亲团聚

- 匹配只生成带分数与理由的候选，不得自动认定。
- 团聚确认必须至少挂一条已接受的候选线索；决定与线索双向留证。
- `family_timeline` 与 `separation_summary` 必须能还原：在哪接收、被哪支队伍的哪个批次
  送走、到了哪个安置点、何时因何依据团聚。

## 物资批次守恒

- `stock_ledger` 为只追加台账：禁止 DELETE 与 UPDATE（触发器强制）。
- 发放/补发减库存；退回回补；人员间转交以成对出入行表达，批次总库存不变；
  补发必须引用原发放行；主管数字修正用冲抵行，不重复入库。
- 已发出的物资不能直接删除，只能通过退回、转交或补发平衡。

## 隐私

- 医疗、儿童、老人资料分别仅限对应岗位；无障碍需求供长者照护岗与安置点工作人员使用。
- 每次敏感读取（无论批准或拒绝）写入 `access_log`。
- 主管可处理线索与回执冲突，但不在医疗/儿童资料的可见岗位内。

## 回执幂等

- 同编号回执：关键内容一致 → 只处理一次并记 `duplicate`；非关键字段差异不重复入账。
- 关键内容不一致 → 不应用任何副作用，入冲突队列并发 critical 预警，仅主管可解决。

## 恢复待办

- 容量预警、失联匹配、药品补给、待确认转运全部存于 `scheduled_jobs`。
- 周期任务有幂等键，重启不重复创建；执行沿原计划时刻续期，错过则贴当前时间保持节奏。
- 单个任务失败置 `failed` 且保留错误信息，下次 `run_due` 重试，不阻断其他任务。
- 转运/出院/返家/跨区调剂发生时，未执行安排按联动表取消或改派，链条可追溯。
