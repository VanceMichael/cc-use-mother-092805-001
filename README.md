# 洪灾安置家庭团聚与救助物资核对

管理洪灾撤离、安置容量、家庭团聚、敏感需求和救助物资。

## 参与方与事实

主要参与方包括省级救灾协调员、地方救援队、安置点工作人员、受灾家庭、医疗与社会服务人员。领域资料记录以下已经确认的事实：

- 泰国洪灾影响17府约57.4万户和180万人
- 灾害造成伤亡并需要持续救助
- 官方预计部分地区水位需要较长时间消退

## 业务约束

- 家庭与人员核验
- 撤离和安置容量
- 寻亲团聚
- 物资批次守恒
- 隐私与恢复待办

`contracts/context.schema.json` 描述资料结构，`fixtures/context.json` 提供不含真实身份信息的示例，`src/news_context_001.py` 负责读取和校验这些资料。

## 后端模块（src/backend/）

安置与家庭团聚后端，纯标准库实现，SQLite 持久化：

- `store.py`：工作表 + 只追加事件日志。接收地点/时间/经办人、家庭拆分原因、
  团聚依据的线索都以事件保留，合并与重启后仍可查。
- `service.py`：领域服务。
  - 无证件人员先建临时档案；同名同年龄段自动生成疑似重复线索，主管确认后才合并；
  - 转运、出院、返家、跨区调剂确认时，未执行的发放计划与待确认安排随之取消；
  - 物资批次只追加流水（发放/退回/转交/补发/调拨/补正），已领取物资不能删除，
    `verify_conservation` 校验批次守恒；
  - 队伍回执按（队伍, 回执号）幂等，关键内容不一致生成冲突交主管核对，
    补正只追加调整流水。
- `access.py`：岗位（接收/儿童保护/老人照护/医护/后勤/协调员/主管）与敏感度
  （一般/儿童/老人/医疗）矩阵，儿童、老人和医疗资料只对相应岗位开放。
- `recovery.py`：`recover_pending` 在应用重启后续接四类待办——容量预警、
  失联匹配、药品补给、待确认转运；重复执行安全。
- `handover.py`：`family_story` 还原家庭为何被拆分、各成员当时在哪里、依据哪些
  线索团聚；`shift_handover` 汇总班次待办、冲突与预警。
- `api.py`：演示用 HTTP 接口（`POST /commands/{命令}`、`GET /queries/{查询}`），
  岗位经 `X-Actor-Id` / `X-Actor-Role` 请求头传入；生产环境应前置真实认证层。

## 开发命令

运行测试：

```bash
python3 -m unittest discover -s tests -v
```

编译检查：

```bash
python3 -m compileall -q src
```

两条命令只读取仓库内文件，不需要连接外部业务系统。
